Aicountly Pay — UI reference

Green and white, light mint surfaces, thin borders, restrained shadow — the same palette as the rest of the fleet, so somebody moving from Books to Pay is plainly still in the same product. Every specimen below is rendered by web/src/styles/pay.css itself.

Colour

Tokens live on :root in web/src/index.css. Light only, deliberately: there is no prefers-color-scheme block and color-scheme: light is declared, because a payment screen gets printed, screenshotted into support tickets, and read on a counter in daylight.

On the two greens. #25b003 is the brand mark: logo, chart fills, tinted surfaces. It is never used for text or for a button label — white on it is about 2.4:1 and fails for anybody reading at an angle in sunlight. --pay-action is 5.6:1 on white and is what every action, link and piece of coloured text uses.

No dark sidebar. The navigation is on --pay-surface with a hairline border, and the active item is a mint fill with green text. A dark rail belongs to a different product.

Metrics

.pay-metrics / .pay-metric. Every card states its basis — over the period, right now, a count — because “collected” means two different things depending on which one it is.

Unavailable is not ₹0.00. A zero that means “no data” and a zero that means “no money” are different facts. A metric that cannot be computed says so, with the reason — a dashboard that conflates the two is worse than no dashboard.

A rise is not automatically good news. --positive is for a metric where up is better. --warning is for one where it is not. More failures is never green.

Panels and tables

.pay-grid is four columns; .pay-span-2/-3/-4 widen a panel. .pay-table-wrap scrolls, with a shadow that appears only when there is something to scroll to.

Forms

.pay-field wraps a label, an input and either a hint or an error. Never both.

A credential field is write-only. The API returns a mask and a test result, never the secret. There is no screen anywhere in this product that can display a provider key back to a user.

Pay Pulse

An insight carries the evidence it was computed from and a confidence, both on the screen. An insight you cannot check is one you cannot trust.

Rules

RuleBecause
Never use --pay-brand for text.2.4:1. Use --pay-action, which is 5.6:1.
Never signal status with colour alone.Badges carry a dot and a word as well as a hue.
Never render a missing number as 0.“No data” and “no money” are different facts.
Never paint a rise green by default.More failures is not good news.
Never show a provider secret.Write-only fields; the API returns a mask.
Never combine the five dashboards.Five questions, five routes.
Never put the app shell on the checkout.The payer is a customer, not a user of this product.
Always state a metric's basis.Over the period, right now, or a count.
Always show an insight's evidence.Otherwise it is an assertion.
Always give a chart a text alternative.Every chart carries an .pay-sr-only data table.
